How the gateway is exposed, how to lock it down, and a tool that audits it the way an attacker would.

The short version

A gateway puts your machines on the network. It speaks Modbus TCP (so SCADA and PLCs can read and control it) and serves a web page (so you can set it up and watch it). Both are meant for a trusted, local network — like every industrial Modbus device, they have no built-in login.

The one rule that matters: keep the gateway on an isolated OT network or VLAN, reachable only by the hosts that need it, and never port-forward it to the internet or put it on guest Wi-Fi.

Harden it

Network

  • Put it on an isolated OT VLAN; allow Modbus (502) only from your SCADA/PLC host.
  • Block ports 80 and 502 at the firewall from everywhere else.
  • For remote access use a VPN, never a public port.

The device

  • Set a web password (Connections → Web page) and send it over USB once.
  • Include the passwords only when you send settings, and keep the config file safe.
  • Keep firmware current from the web installer.

Audit your own gateway

The repo ships a scanner. Run it against a device you own: it scans the ports, probes Modbus and the web page for weak spots, and prints a ranked report.

python security-audit/audit.py 192.168.0.206            # read-only
python security-audit/audit.py 192.168.0.206 --json report.json
python security-audit/audit.py 192.168.0.206 --active  # proves a Modbus write (toggles DO0, restores it)

Only run it against equipment you own or are authorised to test.

Is a gateway reachable?

A quick look only: it asks the device's open /api/status. Browsers block a plain-HTTP request from an https:// page, so this works when you open this page locally or when the controller serves it itself, not from GitHub Pages over https.
