## Found and fixed

- **Empty MQTT values, thousands per second.** Arduino-Pico links newlib-nano, whose `printf` has no float support, so `snprintf("%.4g")` gave "". AN0/AN1 and RS485 payloads were empty, and because an empty "last sent" value means "not sent yet", they were republished every loop and crowded out every other message. Fix: `build_flags = -Wl,--undefined=_printf_float` in `platformio.ini` (+7 KB flash).
- **RTC was 8 h 20 min fast** (probably set to local time as UTC). Set from the PC with `TIME`.
- `run_native_tests.py` crashed on Windows while deleting its temp folder; it now ignores cleanup errors.

## Added: MQTT over TLS (port 8883)

- Settings `mqtt.tls` (off by default) and `mqtt.ca` (PEM, up to 3071 characters). Dashboard: "Encrypt with TLS" and "Broker CA certificate".
- With a CA the broker's certificate is checked, dates against the RTC; with the clock lost the controller does not connect and logs why (not tested). Without a CA the link is encrypted only.
- **Certificate name:** BearSSL matches the configured broker address only against DNS names in the certificate. A certificate listing `192.168.0.138` only as an IP entry was refused; adding `DNS:192.168.0.138` fixed it. Documented in the firmware README and the dashboard.
- `STATUS` reports `mqtt.tls` and `mqtt.brokerChecked`. BearSSL adds about 75 KB flash (24% used).
- The README's old "TLS does not hold a session on this board" did not happen here.

## USB dropped out twice

The board vanished from USB twice while it kept running on the LAN, and once Windows showed "Device Descriptor Request Failed" even with BOOT held (the ROM bootloader, which firmware cannot affect). It came back after reseating the cable, so this looks like the cable or connector, not the firmware.
