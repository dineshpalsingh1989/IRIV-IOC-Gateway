# Session notes, 25 Nov 2026

## Questions answered

**Can the main chip be customised and updated?** Yes. It is an RP2350A. Build your own firmware and load the `.uf2` over USB-C (web installer, or drag it onto the RP2350 drive). Nothing is locked. Install mode lives in the chip's read-only boot ROM, so a bad install can always be redone with the BOOT button.

**W5500 and MQTT on port 8883 (TLS)?** Not a real limit for this firmware. The "1883 only" limit applies when you use the W5500's built-in sockets (`Ethernet.h`). Our firmware runs the W5500 as a plain network card under lwIP (`Wiznet5500lwIP`), so TLS can run in software on the RP2350 with arduino-pico's `WiFiClientSecure` (BearSSL). The main change is at `firmware/src/main.cpp` (`WiFiClient mqttNet` becomes `WiFiClientSecure`) plus how the server is trusted: CA certificate, fingerprint or `setInsecure()`. Checking a CA certificate needs the correct time (RTC). Not tested on hardware yet. `setInsecure()` encrypts the link but does not check who the server is.

**RTC?** Yes, the board has one (datasheet): a PCF85063A on I2C0 (SDA GP16, SCL GP17, address 0x51) with a CR2032 backup cell.

**Can we read the voltage?**
- **CR2032 (RTC battery): no.** It is not wired to an analog pin, and the PCF85063A has no battery-low flag. What we *can* see is the chip's "oscillator stopped" flag: if it is set at boot, the clock stopped while unpowered, which means the battery is flat or missing (or the clock was never set). So you get a yes/no battery warning, only after a power cut.
- **Supply voltage: no.** The RP2350A has only 4 analog pins, and all are used: GP26 = AN0, GP27 = AN1, GP28 = USER button, GP29 = LED.
- What we can read: the AN0/AN1 terminal voltage (Modbus 0x0200, mV) and the chip's internal temperature.

## Done today: firmware 0.3.0

Committed on branch `firmware-0.3.0-rtc` (commit `b17fe66`). Not pushed, not merged to `main`.

- **RTC:** reads the PCF85063A at boot. `HELLO`/`STATUS` report the clock as `ok` (with the time), `lost` or `missing`. New USB command `TIME <unix>`. On **Connect over USB** the installer sets the clock from your PC if it was lost or is more than 2 s off, and warns you to check the CR2032 if it was lost.
- **Version in the dashboard:** a tag next to "IRIV IOC" in the top bar. Not connected: `firmware v0.3.0`. Connected: `controller v0.2.1 · v0.3.0 available`, or just `controller v0.3.0` when it is current.
- **Installer says what is on the controller:**
  - Our gateway: version (up to date / update available / newer than this installer), whether settings are saved, and the clock.
  - Other firmware: "Other firmware", naming CircuitPython or MicroPython when its startup text says so.
  - Empty: a new or empty controller starts in install mode by itself, so it shows up as the RP2350 drive, not as a USB port.
- Checked: firmware builds with no warnings (RAM 19%, flash 15.6%), installer passes the syntax check, register maps match. Not yet tried on a real controller.

## Can the web installer test the IOC before installing?

Only partly. The browser can only talk to code running on the device.

| On the controller | What can be checked before install |
| --- | --- |
| Our gateway | A lot: chip, board, unique ID, version, settings, RTC, and via `STATUS` Ethernet, Modbus, MQTT and RS485 |
| Other firmware or empty | Only USB IDs, the chip named on the install drive, and that the `.uf2` matches it |

Because installing cannot brick the controller, the safe order is: **check → install → self-test**.

## Added later today: controller check before install (also in 0.3.0)

When the gateway is on the controller, the installer now checks the hardware:

- **Put in install mode** runs the check first. If it finds a problem, it lists it and asks before rebooting into install mode.
- **Connect over USB** runs it too, and keeps it live every 3 s, so switching a digital input on lights it up on the page.
- **Beep and blink** shows which controller you are holding (buzzer + fast USR LED for 3 s).

| Check | Pass when |
| --- | --- |
| Ethernet chip | W5500 answered at start-up |
| Ethernet port | Cable in (no cable = note, not a failure) |
| Clock | RTC answers and time is valid |
| Flash storage | Mounts; shows free space |
| Settings | Saved and loaded without problems (none yet = note) |
| Chip temperature | Under 85 °C |
| AN0 / AN1, DI0–DI10 | Shown live for you to judge |

Not possible: testing a controller that is empty or runs other firmware, because no gateway code is on it to answer. For those, install first, then Connect over USB to run the check. The outputs DO0–DO3 are not switched by the check.
